# 下载功能差距与改进方向

本记录以源码和 IDM 官方功能说明为依据；未运行应用或测试，不代表实际性能比较结果。

按功能领域的对照及后续顺序见 [IDM 功能对照](idm-feature-parity.md)。本文件集中记录下载引擎的实现边界。

## 核心差距

- **断点恢复**：下载任务及已完成分段写入用户配置目录；分段先同步到磁盘并计算摘要，再原子更新任务记录。重启后恢复为暂停状态，继续时检查远端强 ETag 或符合强校验条件的修改时间、长度以及本地分段摘要。没有可靠版本标识时默认使用单连接；若用户提供 SHA-256，可分段下载并在发布前校验，但无可靠标识时仍不复用旧分段。已知大小且至少 256 KiB 的安全 Range 下载可使用分段检查点；不支持 Range、大小未知或更小的文件仍从头下载。持久化任务在发布前记录已同步文件的摘要与长度，重启后对缺少临时文件或保留同一硬链接的目标进行后台核对，再恢复完成状态；异常退出及断电场景尚待手动验证。
- **认证与隐私**：记录中不保存 URL 用户名密码，也不保存除常用非认证头之外的自定义请求头；涉及这些字段的任务恢复后需要重新获取链接或登录信息。暂停或失败任务可通过右键更新地址、基本认证及自定义请求头；相同地址保留已完成分段及完整文件的发布记录，更换地址则丢弃旧记录并重新下载，避免跨资源误用相同 ETag。URL 和来源页可能包含签名查询参数，任务记录应存放在用户私有配置目录；当前尚无跨平台加密凭据库。
- 使用用户名和密码的任务可响应同源 HTTP Digest 挑战，支持 MD5、SHA-256、SHA-512/256 及其 sess 变体、auth/auth-int qop 和服务器要求刷新 nonce 的情况。认证挑战仅在当前任务内按完整地址摘要短暂缓存，后续分段可提前认证，过期、凭据更新或服务器拒绝时重新挑战；不写入任务记录。auth-int 在完整读取后校验服务端提供的响应摘要（含 trailer）；若服务端未提供该摘要，则不能据此确认响应完整性，动态分段也不会提前中断待校验响应。Windows 集成认证与显式 NTLMv2 另见[剩余功能推进记录](remaining-gaps-progress.md)；代理集成认证与跨平台 GSSAPI 暂不支持，服务端兼容性和重定向行为尚需手动验证。
- 浏览器扩展可由用户启用同源非分区 Cookie 传递，适用于部分登录下载；跨源资源、分区 Cookie 及其他认证方式仍需单独处理。登录信息不写入任务记录，实际站点行为仍需手动验证。
- **提交去重**：支持能力声明的扩展、原生主机和桌面端使用独立的逻辑请求编号；浏览器会话内同页面同选项重试复用编号，桌面任务记录保留该编号，响应丢失后再次提交可返回原任务。发送前保存尝试状态，先前接收成功或结果不确定时，后续断连不会自动回退为浏览器下载；读取记录失败时也会提示检查任务。编号冲突返回错误，用户移除任务后可重新创建；旧版本仍存在原有行为限制。并发提交、进程中断及会话存储行为尚需手动验证。
- 扩展通过页面资源扫描、响应 Content-Type 被动识别，以及页面世界注入（`extension/page.js`）识别 HLS/DASH 清单和媒体元素请求的常见音视频文件，包括无扩展名地址；注入钩子覆盖 fetch、XHR、媒体元素源和回填媒体元素的 blob 地址，MSE 播放上报播放器取到的清单地址，并对疑似文本清单读取首块内容识别 `#EXTM3U`/MPD。捕获的地址会在浏览器会话内保留，导航或关闭标签页时清理。fetch/XHR 的媒体分片仍不作为完整文件列出，后台未运行期间的请求、注入失败的框架、未提供可识别类型的响应和受浏览器限制的页面仍可能遗漏。用户配置的站点规则文件（`site-rules.json`）可识别无扩展名的下载路径：规则（host 与路径正则、可选扩展名）由原生主机下发到扩展并热更新，桌面端的单页提取与站点抓取使用同一规则表；无效条目会被跳过。该识别逻辑、页面注入兼容性、规则文件编辑生效、会话存储及扩展权限变更尚需手动验证。
- **分段调度**：IDM 描述了在连接可用时拆分最大剩余分段，并让空闲连接协助慢连接。当前队列限制大文件单次领取最多 64 MiB；无未领取范围时，空闲连接可要求剩余范围最大的活动连接让出任务，原连接停止后先同步并记录已写入前缀，再将剩余范围放回队列。同一任务一次只发起一个让出请求，减少同时中断多条连接。该方式会中断原连接并重新请求剩余数据；请求数量、磁盘同步开销、取消及实际速度仍需手动验证。
- **队列并发**：管理器按任务进入队列的顺序和并发上限分配槽位，取消等待任务后继续调度；恢复任务重新排到队尾。夜间队列任务也存入任务记录，API 添加夜间任务时先持久化并保持等待；迁移保留任务 ID、完成动作和已下载分段，运行中的任务需先中断并关闭文件。同一站点的任务共享 32 个并发 HTTP 请求额度，其他站点独立；等待站点及全局连接额度的请求各自按入队顺序领取，排队请求可取消，全局上限改为不限时会唤醒等待连接。队列调度、站点额度的公平性、动态上限及异常退出场景尚待手动验证。
- **速度统计**：任务速度按所有连接的实际写入字节采样，重试流量计入速度但不计入最终进度；停滞时清零。详情曲线按实际秒数绘制，运行效果尚待手动验证。
- **文件完整性**：添加单个任务时可指定 SHA-256，下载完成后先比对再发布；不匹配时保留临时文件并显示错误，停止的任务可更新期望值。没有提供期望值时，详情中计算出的摘要仅用于识别文件，不能证明与发布方一致；实现仍需手动验证。
- **文件命名**：优先使用 Content-Disposition 文件名，再从地址和页面标题推导；URL 的末段只解码一次，支持编码斜杠及百分号，邮件编码文件名支持 B/Q 编码和引号转义，并按声明解码 GBK、Shift_JIS 等字符集。常见音视频、文档和压缩包的 MIME 类型可补充扩展名，过长名称截断时保留合理长度的后缀；Windows 设备保留名包括多重扩展名和上标数字形式。不对通用二进制类型猜测扩展名。没有声明字符集的 URL 保持 UTF-8/Windows-1252 回退，不推测地区编码。特殊服务器响应及不同文件系统仍需手动验证。
- **文件系统与空间**：Windows 根据已打开的临时文件识别 FAT32；已知长度超过单文件上限时在预分配或传输前报错，未知长度和 HLS 合并会在继续写入前检查上限。Windows 的输出文件、发布改名与占名检查支持超长路径（扩展前缀）。同目录的并行任务按预计剩余占用互相扣减空间预检；该预算按目录近似同一分区，暂停任务释放预算。已知大小的普通文件会结合当前用户可用空间与临时文件实际分配量预检，不重复计算已占用空间；未知大小、稀疏/压缩文件或查询失败时由实际写入报告错误，磁盘已满时补充具体提示。空间会被其他进程和并行任务消耗，当前预检不构成空间预留；并行空间预算、其他平台预检及真实介质行为尚需完善或手动验证。
- SHA-256 不匹配后，以相同摘要重试会丢弃失败分段的复用记录并重新下载；如果用户更正了摘要，则可保留已有分段进行新的完整校验。
- **全局限速**：所有任务和连接在读取前共享限速额度，短读归还未使用额度，调整或关闭限速会唤醒等待中的读取；单次突发限制为四分之一秒流量且最多 32 KiB。限速精度、并发公平性及动态调整仍需手动验证。
- **分段详情**：引擎快照包含分段起止位置、已写入前缀、活跃状态和近期写入速度，界面按真实偏移绘制并显示活跃分段速度；单连接流式下载也显示当前写入速度，未知长度在结束前不推测范围终点。重启后展示的是已记录分段，继续前会重新校验。活跃分段不等同于实际 TCP 连接数，逐 TCP 连接速度明细尚未提供。
- **协议兼容**：IDM 支持多种传输协议及浏览器集成；当前引擎覆盖 HTTP/HTTPS 与 FTP/FTPS（隐式与显式 TLS、动态多连接分段、REST 检查点续传、SIZE/MDTM 校验、URL 或站点登录凭据）；FTP 代理链路未支持，MMS 等已废止协议明确不在范围。
- HLS 可解析主清单，按码率顺序尝试音视频合并的兼容画质，并可按用户选择的分辨率上限筛选（清单声明 RESOLUTION 时优先匹配，未声明时退回码率顺序）；对于有限的媒体清单，支持完整资源和字节范围分片、AES-128 加密与 TS 不连续分片、未加密 I 帧专用清单。MPEG-TS 逐段检查包边界并合并为 `.ts`；带 `EXT-X-MAP` 的 fragmented MP4 先下载初始化段，再按原顺序合并为 `.mp4`。MP4 在记录分片前检查容器边界、轨道匹配、解码时间、相对寻址、样本长度和当前媒体数据范围；外部数据引用、加密轨道、绝对偏移或切换初始化段会明确报错，不发布完成文件。初始化段上限 16 MiB，其范围需显式起点；零长度至 EOF 的 MP4 数据块、跨 mdat 的单个运行表及部分复杂样本描述仍不支持。检查不等同于解码或播放器兼容保证。
- HLS 兼容时间范围及不连续序号等不改变分片内容的元数据，TS 的实际不连续分片按原样拼接。分片传输发生临时读取错误时，当前运行会回退未完成分片并有限重试，无须重复下载此前分片。完成的分片同步后保存摘要，续传时检查清单及本地内容，并通过远端版本标识确认资源；提供发布方 SHA-256 时可依靠最终完整校验复用。无法确认的分片会重新下载。重复访问同一字节范围资源时需要可靠版本标识或用户提供 SHA-256；未提供 SHA-256 时，每次响应必须保持相同版本标识。MP4 检查点单独保存格式，不受 TS 的 188 字节对齐要求影响；旧 TS 记录保持兼容。历史 API 标识 `hls-ts` 保留。未结束标签的清单按直播录制：跟随清单追加新分片，清单结束或选择结束录制后发布，普通取消保留检查点并可继续录制；结束录制、暂停和恢复仍需手动确认；直播窗口滚动导致历史分片无法回头校验。AES-128 加密流按密钥地址解密（显式 IV 或媒体序号 IV，单分片上限 64 MiB，同任务内缓存密钥且不落盘）；SAMPLE-AES/DRM 与加密的 I 帧专用清单仍不支持。分片 MP4 点播支持不连续边界，直播期间切换仍不支持；独立音轨按语言选择后由本机 FFmpeg 混流，DASH 支持静态单/多周期与动态直播清单，边界详见[剩余功能推进记录](remaining-gaps-progress.md)；画质上限选择依赖清单的 RESOLUTION 声明；新编写的 MP4 用例及重试、续传、异常退出、真实媒体与播放器兼容性均尚未运行验证。

## 值得改进的限制

- IDM 官方说明续传取决于服务器是否支持；应在下载前后清晰报告实际能力，遇到不支持续传或资源变化时保留可恢复数据并告知用户，而不是静默拼接不一致的文件。
- IDM 官方说明某些服务器会错误地改变修改时间，并提供忽略修改时间的选项。应优先使用强 ETag，明确弱校验或无校验时的风险，避免默认忽略资源变化导致文件损坏。
- 对分段请求校验状态、范围和长度，禁止错误响应跨分段写入；服务器忽略 Range 返回完整响应时，丢弃旧分段并使用新的完整响应退回单连接。临时网络故障及 408、429、500、502、503、504 采用有限次数退避重试，429/503 的 `Retry-After` 在同源请求间共享；超过自动等待上限时报告错误，不提前重试。网络读取连续阻塞 30 秒时取消当前请求并重试，不把磁盘写入或限速等待计入超时。后续仍需按站点自适应连接数；超时和重试行为尚待手动验证。
- 服务器未声明 `Accept-Ranges` 时，满足大小及版本校验条件的任务会尝试范围请求，收到正确的 206 后确认支持；明确声明不支持或忽略范围请求时使用单连接。行为仍需手动验证。
- 范围请求返回 400、403、405、412、416 或 501 时，重新获取完整响应，成功后清除旧分段并以单连接下载；如果完整请求也失败则报告错误并保留旧数据。该行为仍需手动验证。
- 续传记录保存最终资源地址的 SHA-256 摘要，地址或校验标识变化时不复用旧分段；没有用户提供的 SHA-256 时，分段请求跳转到不同地址会退回完整下载，避免不同资源碰巧使用相同 ETag 而被拼接。若用户提供 SHA-256，则允许本次分段使用不同目标，并在发布前校验整个文件；不匹配时保留临时文件并报错。旧记录缺少地址摘要时会保守地重新下载。
- 同站点 429/503 的冷却期限会在任务和连接之间共享，重定向目标也在跳转前检查；等待全局连接名额后再次检查站点冷却，冷却等待不占全局名额。期限结束后添加最多 250 毫秒的随机延迟，减少并发连接同时恢复造成的突发。若服务器要求等待超过自动等待上限，当前任务报错，后续请求在期限内也不会提前发送。重启应用后的冷却期限不会保留；并发场景尚需手动验证。
- 完成文件时使用不覆盖已有目标的操作；如果下载期间出现同名目标，保留临时文件并报告错误。Windows 上针对文件临时占用或访问受限进行有限重试，并允许取消；权限错误仍可能在重试后报错。已同步并记录完整摘要的文件在发布失败后可重新核对本地数据并直接重试发布，无须重新访问服务器，即使登录信息未随任务保存也可尝试；本地数据变化时清除旧发布记录并回到下载流程，需要凭据时先提示更新。非 Windows 平台依赖文件系统的硬链接支持，尚需覆盖不支持硬链接的文件系统。发布重试、恢复及占用场景尚需手动验证。
