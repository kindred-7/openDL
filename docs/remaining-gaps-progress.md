## 实现边界

MP4 初始化段复用的结构指纹包含电影时间刻度、轨道显示信息、处理类型和完整编辑列表，避免忽略显示及时间映射差异。指纹版本更新后，旧版点播缝合检查点会重新下载；已有旧版直播检查点无法安全续录，需重新开始。周期下载入口允许音视频使用各自清单来源及独立检查点。

HLS 独立双轨结构不兼容时，源码先检查周期边界及不连续序号，再分别下载周期轨道；FFmpeg 读取两轨首个解码帧时间，为较晚的轨道补前导静音或画面，再重新编码拼接。支持至多 8 个周期、起始差最多 60 秒；相同不连续序号但分片边界不对应、编辑列表、帧率取整、长时间间隙及周期尾部等情况仍需实机确认，不能据此断言所有音画同步正确。该路径尚未构建或运行验证。

文件签名通过系统 [WinVerifyTrust](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/nf-wintrust-winverifytrust) 的 Authenticode 策略验证，只有零返回值通过；验证在后台进行，不代表文件没有恶意行为。更新清单使用独立的 Ed25519 发布信任根，见 [签名发布协议](updates.md)。

分离签名源码支持 Base64 的 Ed25519 原始签名（覆盖文件 SHA-256 摘要字节）、OpenPGP EdDSA 分离签名（v4 数据包，按签名自带 SHA-2 系哈希计算 H(哈希区 || 尾部 || 文件内容)，见 RFC 4880 §5.2.4）及 Minisign 的 BLAKE2b-512 预哈希签名。Minisign 校验密钥编号、文件签名和可信注释签名，公钥支持 Base64 或公钥文件内容；旧版非预哈希（ED）签名也支持，但需整体读入文件（上限 64 MiB），超限明确拒绝。使用与现有 x/net 依赖一致的 x/crypto v0.57.0。OpenPGP 同时支持 v4 的 RSA（PKCS#1 v1.5）与 ECDSA（P-256/384/521）签名；分段长度数据包与其余算法明确拒绝。上述格式仍需使用真实发布方签名手动确认兼容性。

Minisign 可信注释限制为有效 UTF-8，拒绝 NUL、非制表符控制字符及过长内容，避免控制字符造成显示歧义；注释本身仍需通过全局签名验证。

OpenPGP 签名的子包必须具备完整的长度封装；尚未实现其关键子包语义或签名有效期，因此遇到关键子包或签名有效期声明时拒绝该签名。当前只用提供的主公钥进行数学签名校验，不验证公钥的身份认证、撤销、有效期或签名子密钥绑定，不能将通过结果理解为完整 OpenPGP 信任验证。

分离签名验证前后重新读取 SHA-256，并对比文件身份、大小和修改时间；发现变化时拒绝发布。OpenPGP 和 Minisign 的文件读取也响应任务取消。上述检查不能排除检查结束后的外部修改。

任务详情中的签名状态描述上次验证结果，并不持续监控文件变化。手动验证在调用系统信任检查前后比较摘要、文件身份、大小与修改时间；要求签名的下载也会对比签名检查前后的摘要，发现变化时不标记通过。如需确认当前文件，应重新验证；这些检查不能保证检查结束后文件永远不变。

已发布文件的中断恢复在签名检查后重新读取摘要和文件身份，确认与恢复前一致后才恢复完成状态；检查结束后的文件变化仍需重新验证。
手动重新验证前会先保存旧的通过状态失效，避免验证中断后恢复旧结果；保存失败时提示错误，不把本次结果标记为已保存。

NTLM 使用 [Azure/go-ntlmssp](https://github.com/Azure/go-ntlmssp) 的 NTLMv2 实现，不把 NTLM 回退等同于 Kerberos。每次协商使用独立连接，避免已认证连接泄漏给其他任务；代价是分段请求需要再次协商，不能据此宣称已达到 参考下载器 的连接复用性能。
Linux/macOS 的 GSSAPI 会话源码通过 `gssapi` 构建标签和 cgo 启用；Linux 需要 MIT Kerberos GSSAPI 开发库，macOS 需要系统 GSS 框架。共享 HTTP 层传递 TLS 通道绑定应用数据，后端构造原生绑定。仅 Kerberos 策略获取 SPNEGO 凭据并在发出令牌前调用 `gss_set_neg_mechs` 限定为 Kerberos；NTLM 依赖系统安装的机制及凭据。独立 NTLM 挑战指定 NTLM 机制，且仅接受 `NTLMSSP` 原始令牌；非原始格式明确拒绝。实际协商机制及 Kerberos 双向认证在完成后检查。该路径尚未构建或实机验证，默认构建仍不启用。

代理集成认证的 HTTP 路径使用独立 HTTP/1.1 连接；HTTP 和 CONNECT 路径都处理成功响应中的最终认证令牌并检查协商结果。CONNECT 的 407 支持有明确长度或分块正文，解码正文限制为 64 KiB；无法确定正文结束位置或协商期间关闭连接时明确失败。响应头限制为 64 KiB，隧道握手响应取消与超时。代理认证兼容性与连接隔离仍需实机确认。
代理集成认证按目标检查代理绕过规则，直连目标返回 407 时不会向其发送代理认证令牌；HTTPS 代理的 CONNECT 在代理 TLS 握手成功后发送。HTTP 目标和 CONNECT 的 HTTPS 代理认证均从经过验证的代理证书生成通道绑定；HTTP 路径在重建隔离连接时要求证书与挑战响应一致。需要支持通道绑定的代理实机确认。
HTTP 站点经 HTTPS 代理时，站点认证不会误用代理证书作为站点通道绑定。站点使用自定义 TLS 拨号时，也在发送认证令牌前检查已验证的站点证书及其一致性。同一个 HTTP 连接同时需要站点和代理集成认证时，源码在独立连接上依次处理代理与站点挑战；HTTPS 目标的代理认证通过 CONNECT 处理。组合场景仍需实机确认。
Digest `qop=auth` 在服务器提供响应认证信息时校验 `rspauth`；`auth-int` 还将响应正文纳入校验。服务器未提供该信息时不能据此声称完成服务端身份验证。
Digest 响应如果仅提供 `nextnonce` 等非认证参数，不要求它同时提供 `rspauth`；如果提供了响应认证参数，则仍要求完整且匹配。响应处理成功后更新匹配的缓存 nonce；乱序的旧响应不会覆盖已更新的 nonce。
同一任务按站点、realm 和 nonce 分配递增的 Digest `nc`，并在校验 `rspauth` 时使用对应值；计数仅保存在进程内。并行请求到达顺序不可保证，一次性 nonce 服务器仍可能要求重新协商。

显式 NTLM 认证成功后遇到跨源重定向，会释放原认证连接并用常规请求继续；只保留安全的协商和范围请求头，目标站点不会收到原站点的登录信息。目标站点若显式配置了 Windows 集成认证，按其自身策略处理。

跨站媒体清单、分片和密钥请求，以及跨站重定向，不接受 URL 中嵌入的用户名与密码，避免 HTTP 客户端从地址自动生成 Basic 认证；目标站点仍可使用其明确配置的 Windows 集成认证。

周期同步只适用于带 ETag 或有效 Last-Modified 的普通 HTTP(S) 文件；没有可靠版本信息时报告原因，不凭文件名猜测变化。小文件同样记录远端版本。旧文件被用户修改时取消自动替换；固定 SHA-256 仍然执行，版本变化后若摘要不匹配，必须由用户更新期望值。关闭应用期间不执行探测；重启后重新计算下一次周期。失败或取消后的 `.part` 可通过原任务继续，旧文件保留到最终成功发布。

同步探测遇到 HEAD 不支持时，按下载重试层返回的 HTTP 状态回退到单字节 GET；304 也需要与上一次的最终资源地址匹配，否则启动完整更新，不把不同重定向目标的相同版本标识当作未变化。

HEAD 成功但未返回版本标识时，也尝试单字节 GET；对 206 响应校验范围和声明长度，避免把错误响应的头部当作资源版本。
单字节 GET 会读取完整响应并处理认证尾部；Digest `auth-int` 的 HEAD 或无正文响应会在响应头包含认证信息时立即校验。若回退 GET 被服务器当作全量响应且使用 `auth-int`，则拒绝把未读取完整正文的响应作为同步依据。

同步探测会移除任务自定义请求中的条件和范围头，再设置本次探测所需的条件；无效 ETag 不会遮蔽有效的 Last-Modified。续传的 If-Range 仍使用更严格的版本标识规则。
同步周期变更会使正在进行的旧探测失效；旧结果不能触发下载或覆盖当前任务错误，即使同步已关闭后再次启用。

双轨任务在完成并发布后清理属于该任务的音视频临时轨道；发布失败、暂停和取消时保留轨道以供恢复。发布中断后仅在最终文件或待发布文件完成既有校验并恢复成功时清理。AES-128 音视频分片恢复时从首个加密分片重新获取，避免把独立密钥地址的变化误认为分片未变。

恢复独立音轨临时文件时，打开后核对文件身份与打开前检查的路径一致，避免对检查和打开之间被替换的文件进行截断。

HLS 主清单在开始下载前按画质顺序寻找可用的视频和音轨组合；某个画质缺少所选语言、清单无法读取或仅提供当前不支持的独立音轨直播时，可尝试其他符合画质上限的画质。清单请求次数仍有上限；已开始下载的轨道不会自动切换，以免混入不同内容。
同一音轨组有多个符合语言条件的候选时，按语言匹配、默认和自动选择顺序尝试；无法读取某个候选时可回退到同组其他候选，仍受清单请求次数限制。
HLS 点播媒体清单可切换初始化段地址并保留 fMP4 不连续边界；兼容结构按原路径复用。单轨及满足周期对齐条件的独立双轨点播遇到不同结构时，源码按独立周期下载并交给 FFmpeg 重新编码；内嵌多轨仍明确失败。被跳过的初始化段有检查点，回退路径的周期轨道也有独立检查点。直播窗口切换仍明确拒绝；这些路径尚需实机确认。
HLS 清单解析保留每个分片的不连续序号，按 `EXT-X-DISCONTINUITY-SEQUENCE` 基值及后续不连续标签递增，并将非零序号纳入点播计划身份。该信息仅为后续跨音视频清单对齐提供基础，不能单独证明轨道时间同步。

单轨 DASH 和直接提供媒体清单的 HLS 使用首次解析的清单开始下载，避免在选轨与下载之间再次请求造成内容或资源地址变化；HLS 直播后续仍按既有流程刷新清单。

HLS 主清单中的 `EXT-X-SESSION-KEY` 作为预加载提示处理，不会单独触发密钥下载，也不会作为媒体清单的解密状态；实际分片仍根据媒体清单中的 `EXT-X-KEY` 解密，不支持的加密方式依旧报错。
AES-128 的显式 IV 支持省略前导零的十六进制整数，按 128 位左侧补零；超长或非十六进制值仍会拒绝。

普通 HLS AES-128 分片可使用字节范围，包括带明确 IV 的初始化段；先校验密文范围和长度，再按分片边界解密并校验输出。I 帧专用清单需要不同的范围解密规则，仍不支持。
同一 HLS 分片同时声明 identity 和其他密钥格式时，可使用 identity/AES-128；只有不支持的格式或加密方法冲突时明确失败。identity 的密钥格式版本列表只要包含版本 1 即可使用。
服务器声明了密文长度时，提前结束的响应会作为可重试读取错误处理，不会先误报填充错误。
AES-128 分片的下载限速和流量统计作用于实际读取的密文；解密后的写入只更新文件进度和文件系统大小检查，避免重复计费。

DASH 点播若未声明总时长，仍可解析有限 `SegmentTimeline`；无界重复必须由下一段起点或周期终点限定。分片模板生成重复媒体地址时会拒绝，避免把相同分片错误拼接成完整文件。

多周期 DASH 和 fMP4 HLS 清单至多接受 64 个周期；兼容初始化段可无损缝合，结构不同需要转码时仍限 8 个周期。DASH 周期自带时长或由相邻起始时间、总时长推算，静态多周期可逐周期选取并展开 SegmentBase 索引。点播检查点记录被跳过初始化段的计划位置和待平移状态；恢复时仍需确认其远端强版本标识，无法确认时退回安全前缀。旧版检查点按指纹版本规则处理。这些路径尚未构建或实机验证。

结构指纹现在覆盖完整样本描述和 trex 默认值，避免仅凭编码名称误认不同编码参数兼容。旧指纹检查点的点播轨道重新下载；带旧指纹的直播检查点不能安全重建历史内容，恢复时明确要求重新开始录制。
静态多周期 DASH 遇到结构不同的初始化段时，源码回退为按周期下载独立文件，由本机 FFmpeg 解码拼接并重新编码（视频 MPEG-4、音频 AAC）；兼容结构仍使用原来的无损拼接。回退要求每个周期输入仅有一条轨道；不同视频尺寸按初始化段尺寸的最大宽、高统一画布并保持比例，不足部分补黑边，尺寸上限为 7680。周期轨道使用独立检查点，暂停或重启后按现有规则验证本地分片和远端版本后续传。混流结果仍经过原有发布前校验。该路径尚未构建、测试或实机验证，视频画质、画面尺寸和声道布局会因转码变化，不支持直播。
任务列表在 FFmpeg 执行期间显示“重新编码中”。周期轨道按任务身份命名，成功发布或更换来源后清理；取消或失败时保留以便续传。应用异常退出可能遗留早期版本的 `.opendl-period-*.mp4` 或 `.opendl-period-output-*.mp4`，因没有可验证的任务归属记录，不自动清理这些随机文件。
SegmentTemplate/SegmentList 的时间刻度、presentationTimeOffset 和周期时长保留在分片计划和检查点身份中。周期转码源码保留输入时间戳，并按各轨清单偏移映射到周期时间、裁掉周期外的数据，再交给 FFmpeg 拼接；不足周期时长的画面不会自动补齐，实际音画对齐、空隙和周期边界仍需手动确认，不能据此声称所有时间轴均已正确处理。
字节不同但结构指纹相同的初始化段，复用前还会走完整的初始化段容器校验；多周期分片计划身份包含周期编号和初始化段标记，防止同一资源地址重新分配周期后误用旧计划。

多周期选轨要求每个周期都提供清单声明的音视频类型，缺失时拒绝生成不完整文件。MP4 分片时长可继承初始化段 trex 的默认值；单个 MP4 含多条轨道时，各轨时间刻度不能共用一个平移量，周期切换明确拒绝。独立音视频轨各自拼接后再混流的路径不受此限制。
静态多周期清单中，省略的周期起点按前一周期起点与声明时长推导；相邻周期的实际边界优先采用后一个周期起点。无法推导或起点不递增时明确拒绝，避免把多个周期都当作从零开始。

单周期 DASH 的起始时间按时长语法解析，接受 `PT0S`、`PT0.000S`、`P0D` 等等价写法；非零起始时间只参与从总时长推算周期时长，周期自带时长时无需调整。

DASH 清单中单个表示的地址或封装不受支持时，可继续选择同类型的其他可用表示；如果必需的视频或音频没有可用表示，任务明确报错，不省略该轨道。
DASH 选中的表示在读取索引时失败，可在开始写入媒体文件前尝试同类型其他符合画质或语言要求的表示；尝试次数有限，下载开始后不切换表示。
DASH 视频表示未单独声明高度时继承所属 AdaptationSet 的高度，以便正确应用画质上限；表示自身的高度优先。

SegmentBase 支持以独立文件提供完整初始化段，也支持通过字节范围提供初始化段；索引和媒体范围通常绑定同一资源的可靠版本标识。服务器没有强版本标识时，只有设置了最终 SHA-256 才允许下载，并继续检查最终地址和资源大小；最终文件摘要不匹配时不会发布。
DASH 索引和嵌套索引的实际网络读取也计入速度与流量配额，并遵守下载限速；读取结束时仍处理响应尾部认证。
索引或嵌套索引读取遇到暂时性中断时，会在同一表示上有限重试并重新建立索引计划；重试仍失败后才考虑其他表示。
HLS/DASH 清单和 HLS 密钥读取同样计入速度与配额，有限长度响应读取到末尾后处理认证尾部。
点播清单读取遇到暂时性中断时按现有上限重试；密钥读取失败沿用分片的有界重试。点播清单的格式和认证校验错误不会作为网络中断反复重试；直播刷新保留原有重试策略。
SegmentList 如果已经明确给出媒体地址或媒体范围，可顺序下载完整分片，即使条目还包含用于子分片定位的独立索引；不依赖该索引推导缺失的媒体地址。

HLS 直播去重使用分片地址及字节范围的单向摘要，不再将完整分片地址写入新的检查点；旧记录在读取后转换为兼容摘要，下次保存时移除原地址。旧格式仅按地址去重，无法恢复同地址不同范围的精确信息。

清单声明媒体序号时，新直播检查点也将序号纳入分片身份，支持服务器复用同一地址的不同分片。旧检查点没有序号，恢复时仍沿用其原有的地址去重精度。
双轨直播的进程内去重也使用媒体序号、地址与字节范围的摘要，避免单一地址承载不同序号时跳过后续分片；未声明序号的清单仍只能按地址与范围区分。
独立双轨直播按轨道保留跨清单刷新的字节范围资源版本信息；最多保留最近 16384 个不同资源，较早记录淘汰后不能再保证跨批次版本一致。查询参数变化会被视为不同地址。该路径尚未实机确认。

DASH 直播刷新时继续使用初次选中的表示身份，不因新出现的更高画质或音轨而切换；表示暂时缺失时等待后续清单，身份不唯一或初始化信息变化时失败。初始化地址比较包含查询参数，因此签名地址轮换也可能触发失败；直播窗口滚动可能导致缺失期间的分片无法补录。该行为仍待实机确认。

当前没有运行构建、测试、应用或运行时验证，所有实机确认由用户手动进行，按 [手动验证清单](manual-verification.md) 逐项记录。总体目标仍在推进，剩余工作不能以这些源码改动替代。
