# 手动验证清单

应用未运行构建、测试或实机检查；下列项目由用户手动完成。全部通过前，功能对照表的“待人工验证”不解除，也不宣称“全部复刻”。逐项记录结果后可回填 [功能对照](idm-feature-parity.md)。

建议执行顺序：维护类（导出/导入、扫描、清理）成本低先跑；随后基础下载与队列计划；媒体矩阵（多周期、动态 MPD、双轨直播、周期转码）最耗时放中段；浏览器集成依赖原生主机注册，排在安装脚本之后；完整性与更新放最后（需配合发布源）。

## 基础下载

- [ ] HTTP 200 / 206 / 不支持 Range 的服务器各下一文件，确认进度、续传提示与最终文件一致
- [ ] 下载中断网、恢复网络，确认自动重试后完成；重启应用后继续，确认分片与摘要校验通过
- [ ] 下载中替换远端文件（ETag 变化），确认续传拒绝拼接并提示；带发布方 SHA-256 时确认摘要不匹配不发布
- [ ] 磁盘空间不足、目标文件被占用、保存目录无权限，确认报错清晰且部分文件可继续
- [ ] 跨卷保存目录（或 FAT U 盘）、300+ 字符深度目录，确认发布与创建成功
- [ ] 三个已知大小任务同分区并行，确认空间预算按合计拦截；暂停其一后放行

## 媒体下载

- [ ] TS 与分片 MP4 点播合并，产出可播；画质上限选择生效
- [ ] AES-128 加密流（媒体序号 IV、显式 IV、字节范围分片、带 IV 初始化段）各下一例，确认解密正确
- [ ] 未加密 I 帧专用清单可下载；加密 I 帧清单明确拒绝
- [ ] TS 与分片 MP4 直播跟随增长；HLS 清单正常结束或选择“结束录制并保存”后发布，普通取消不发布并保留可恢复内容；手动检查结束请求期间正在下载的分片及后续校验
- [ ] DASH 单轨及双轨直播选择“结束录制并保存”后完成当前批次并发布；取消或异常退出后重新开始：已有单轨临时文件应保留并提示无法安全续录，不能重复追加
- [ ] 本地接口和 `opendl-cli finish-live` 只接受正在录制的任务；重复请求、普通下载、未知编号和旧版接口应明确失败；接受请求后通过任务状态确认最终发布结果
- [ ] 请求结束直播后任务显示“正在保存录制”，校验或重新编码阶段显示相应状态；接口快照正确反映录制、收尾和完成，失败或重新开始后不残留收尾状态
- [ ] 结束请求发生在直播清单刷新、刷新失败或重试等待期间时，应使用已完成批次收尾；双轨刷新中途请求结束不得只追加一侧新窗口，同时普通取消仍不发布
- [ ] 结束请求在清单刷新间隔、网络请求或重试等待期间应唤醒并收尾；请求在分片下载期间应等待当前批次完成，重复结束与普通取消同时发生时不得重复发布
- [ ] 直播清单读取受限速或流量配额阻塞时，结束请求应唤醒清单读取并收尾；分片下载期间的限速和配额仍遵循当前批次规则
- [ ] HLS/DASH 独立轨道直播中，同一个字节范围资源跨多次清单刷新时保持版本标识一致；资源版本变化或缺少可靠标识时应拒绝混入，普通不同资源仍可继续下载
- [ ] 独立音轨直播（音视频分离）录制后 FFmpeg 混流，音画完整；点播双轨行为不变
- [ ] 双轨直播的音频或视频重复使用同一分片地址但媒体序号递增时，确认新分片不会被去重丢弃；无媒体序号时记录地址去重限制
- [ ] HLS 点播切换兼容初始化段或经过 fMP4 不连续边界后可正常拼接；单轨及独立双轨结构不兼容触发周期转码，内嵌多轨应明确拒绝；直播切换应报错，不应无限等待
- [ ] HLS 独立双轨结构变化时，检查不连续序号相同、不同、周期数不同，以及未声明不连续的初始化段切换；检查两轨起点不同、分片边界不同、编辑列表、不同帧率和周期接缝的音画同步，以及取消、重启和缺少 FFmpeg 滤镜时的处理
- [ ] HLS 双轨起始时间戳为较大的正值或负值、两轨仅相差数毫秒时，检查时间偏移不会因日志中的小数显示精度丢失；缺少时间戳时应明确失败
- [ ] HLS 双轨输入包含大量或超长容器元数据时，首帧时间提取不应受诊断日志大小上限影响；无有效帧时间时应失败
- [ ] 初始化段仅在电影时间刻度、编辑列表、轨道旋转矩阵、尺寸或处理类型上发生变化时，不应误判为兼容；点播按不兼容结构处理，旧版缝合检查点和直播恢复按提示处理
- [ ] HLS 和 DASH 点播包含 9 至 64 个兼容周期时可继续缝合及恢复；超过 64 个周期应明确失败，超过 8 个周期且结构不兼容时应提示转码周期上限
- [ ] HLS 和 DASH 点播在兼容初始化段切换前、切换后首片前及首片后暂停或重启；强 ETag 未变化时应正确续传，初始化段版本变化、缺少强标识或校验失败时应从安全位置重新下载，检查时间轴和输出内容
- [ ] 在尚未发生周期平移的已保存前缀中修改或移除后部资源后恢复：保留的前缀应重算解码结束时间，再切换周期时不得沿用旧前缀的结束时间；已平移的旧前缀校验不完整时从头重拼
- [ ] HLS 不连续序号缺省为零；显式基值和后续不连续标签递增，重复、位置错误或数值溢出时应明确拒绝；同地址不同序号不复用旧点播计划
- [ ] 多周期 DASH（如带广告插播）产出单一可播 MP4、接缝时间连续；初始化段仅打包时间戳不同时可无损拼接；含重复初始化段的点播任务暂停后从头下载，单周期点播仍可续传
- [ ] 多周期初始化段编码名称相同但样本描述或 trex 默认值不同时应拒绝直接拼接；旧结构指纹点播检查点重新下载，旧直播检查点提示重新录制
- [ ] 静态多周期 DASH 初始化段结构不同：分别验证单轨与独立音视频轨触发周期转码，接缝、音画与输出格式正确；不同分辨率及宽高比统一画布且不拉伸；多轨输入、超限尺寸、缺失 FFmpeg/编码器时明确失败；取消、重启、磁盘不足与校验失败不发布不完整文件
- [ ] 静态多周期 DASH 混用 SegmentBase、SegmentList 和 SegmentTemplate 时，检查索引选轨回退、各周期时间刻度与 presentationTimeOffset、强版本标识、兼容缝合及不兼容转码；暂停、重启或索引变化后检查续传结果
- [ ] DASH 仅音频直播刷新清单时应继续追加音频；首个候选是 SegmentBase 但还有其他直播表示时应回退，全部候选均为 SegmentBase 或直播刷新切换到 SegmentBase 时应明确报错
- [ ] DASH 直播刷新时新增更高画质或更优音轨，不应切换已选表示；已选表示暂时消失后重新出现可继续录制，身份不唯一、初始化地址或编码参数变化时应报错
- [ ] 周期轨道下载期间暂停、重启及恢复：验证已完成分片按远端版本复用，远端改变时重新下载；发布成功和更换来源后任务所属周期文件清理，失败或取消后保留
- [ ] 不同时间刻度、非零 presentationTimeOffset、音视频起点不同及周期前样本的转码：检查起点、空隙、接缝和音画同步，确认 FFmpeg 输出没有截掉有效内容
- [ ] 周期媒体超出下一周期起点时只保留周期内内容；音视频时长短于周期时检查接缝和缺口，当前不会自动补齐缺失画面
- [ ] 周期转码期间任务列表显示“重新编码中”，取消后状态恢复；异常退出后检查 `.opendl-period-*` 遗留文件及磁盘占用
- [ ] 结构指纹相同但新增不支持数据块或内容保护的初始化段应拒绝；相同分片地址重新分配到不同周期后不得复用旧计划
- [ ] 多周期清单某一周期缺少声明的音轨或视频时应拒绝；验证使用 trex 默认样本时长的单轨 MP4，含多轨的 MP4 周期切换应明确拒绝
- [ ] 多周期清单省略后续 Period@start 时，按前一周期时长推导；后续显式起点优先，无法推导或起点不递增时应报错
- [ ] 动态 MPD 直播录制（单轨与音视频分离双轨）随播放增长、停止产出可播 MP4；直播的多周期与 SegmentBase 清单明确拒绝
- [ ] 导入任务列表：合法行建任务、重复地址跳过、表头与 BOM 干净；Ed25519 签名设置重启后保持
- [ ] SAMPLE-AES/DRM、I 帧加密清单等不支持项确认报错明确

## 浏览器扩展

- [ ] Windows 安装后，应用安装目录的 `extension` 包含 `manifest.json`、`_locales`、资源文件和安装说明；Chrome / Edge 从该目录加载后可连接桌面端。
- [ ] 设置入口打开设置面板，开启浏览器登录状态时请求 Cookie 权限；拒绝授权后保持关闭，重新打开弹窗后设置和授权状态一致。
- [ ] 开启登录状态后在浏览器扩展管理页撤销 Cookie 权限，重新打开弹窗应在资源和任务面板提示当前下载不会使用登录状态；重新授权后提示消失。
- [ ] 扩展弹窗保持打开时撤销 Cookie 权限，登录状态开关和权限提示同步更新；后续新任务不再读取 Cookie，已发送到桌面端的凭据不受此操作追溯影响。
- [ ] 在登录设置读取或保存尚未完成时撤销 Cookie 权限，最终界面不得显示已启用，并提示重新授权。
- [ ] 键盘打开设置后焦点进入面板；返回资源、再次点击设置按钮或按 Esc 均可退出，焦点回到可见控件。
- [ ] 资源与任务标签支持左右方向键、Home 和 End 切换，Tab 只停留在当前选中标签，读屏可关联对应面板。
- [ ] 设置读取失败时可在设置面板重试；等待或失败期间无法发送资源，但可重新扫描和修改接管开关。
- [ ] 登录设置读取失败提示不被扫描状态覆盖；在设置中重试成功后提示消失且发送操作恢复。
- [ ] 在线文档格式设置读取和保存失败均可单独重试；无效输入和保存失败显示对应提示，成功保存后格式规范化，英文界面显示英文文案。
- [ ] 开启接管并配置 `log`、`csv`、`json`、`md`，分别打开对应格式的顶层文档，确认 `text/plain` 的 `.log` 按 `log` 识别；HTML 页面即使 URL 后缀相似也不弹窗。
- [ ] 在线文档格式设置显示支持的响应类型和限制，中英文文案与实际行为一致。
- [ ] 桌面应用分别指定亮色、暗色和跟随系统，插件背景、文字、焦点和主题色保持一致；断开桌面后使用缓存主题，未获取主题时跟随系统。
- [ ] 登录同源站点后，从资源列表分别单项和批量发送下载，确认能使用登录状态；跨源、分区 Cookie 和浏览器下载接管按界面说明处理，不向其他来源传递 Cookie。
- [ ] 使用相对路径和 `base` 元素的 `srcset` 页面扫描资源，确认资源地址解析到页面实际使用的绝对地址。
- [ ] 添加匹配无扩展名链接或网络请求的站点规则，点击重新扫描后确认规则立即生效；部分页面框架无法读取时，即使没有识别到资源也应显示提示。
- [ ] 站点规则匹配页面文本中的无扩展名地址，并确认百分号编码的文件名扩展名在桌面规则和扩展中的匹配结果一致。
- [ ] 资源地址含非 UTF-8 百分号编码文件名时，普通和百分号编码的 ASCII 扩展名仍可识别，不因解码异常丢弃整个地址。
- [ ] 无扩展名的 `download` 链接和成功返回 `Content-Disposition: attachment` 的 GET 请求出现在资源列表；确认普通接口请求和失败响应不被误报，并确认不会保存响应头。
- [ ] 页面中的 `.log`、`.txt`、`.csv` 和 `.json` 文件链接可在资源列表中识别；这些后缀不会因此被加入浏览器下载自动接管白名单。
- [ ] 在任务面板批量发送时能看到成功、失败或待确认提示；带浏览器登录状态的下载在桌面确认窗口修改地址后不再沿用原 Cookie。
- [ ] 扫描和重新扫描期间显示读取状态，旧资源不可发送；扫描失败后不显示旧列表，并可重新扫描。
- [ ] 底部重新扫描按钮显示刷新图标，标签和键盘焦点清晰可见。
- [ ] 扫描过程中切换页面、同地址刷新或通过 History API 跳转时，扩展提示重新扫描，不展示旧扫描结果。
- [ ] 扫描完成后保持弹窗打开并触发页面导航，旧列表不可再选择或发送；重新扫描后可操作新结果。

- [ ] 点击下载白名单类型自动接管进 OpenDL；Alt+点击强制接管；Shift+点击放行；弹窗总开关有效
- [ ] 接管时桌面应用未运行或提交失败，确认浏览器原下载恢复（不丢任务）
- [ ] 接管时桌面端确认接收后才清除已取消的浏览器记录；交接结果不确定时保留记录且不自动创建重复下载，明确拒绝时检查浏览器回退。
- [ ] 页面嗅探：fetch/XHR/媒体元素/blob、无扩展名地址、多框架各验一例
- [ ] 对同一媒体或清单地址分别返回 2xx 和 404/500，确认页面脚本嗅探只记录成功的 fetch/XHR 响应；页面上独立存在的链接仍可显示。
- [ ] 页面脚本对 GET 和 POST 请求分别返回媒体或清单内容，确认页面注入的 fetch/XHR 嗅探不将 POST 响应作为可直接 GET 下载的资源；独立 DOM 链接和性能记录仍可能提供同一地址。
- [ ] GET、POST 和失败响应分别转为 Blob（包括先克隆响应的情况）并交给媒体元素，确认已知非 GET 或失败响应不被 Blob 来源机制当作可重放下载地址。
- [ ] 后台响应嗅探对 GET 与 POST/HEAD 的媒体、清单和附件响应分别检查，只有成功的 GET 响应会进入后台资源缓存。
- [ ] 站点规则本地编辑热生效、远程规则源同步生效（本地优先）；原生主机断连后行为明确
- [ ] 桌面端断连或规则刷新超时时重新扫描，仍可查看已有规则的结果，并提示站点规则刷新失败；恢复连接后重新扫描不再提示。
- [ ] 原生主机断连后恢复桌面端，立即点击重新扫描应主动尝试重连并读取规则，不必等待后台定时重连。
- [ ] 多框架页面同时重新扫描时规则刷新请求可共享；原生主机断连重连期间旧连接的迟到响应不覆盖新规则。
- [ ] 移除站点规则后重新扫描，仅由旧规则识别的地址从列表消失；同时由下载链接或媒体元素识别的地址保留，刷新失败时保留旧结果。
- [ ] Firefox：manifest-firefox.json 加载、注册脚本、持久运行各验一例（需自行签名保活）；背景脚本经 background-firefox.js 以模块顺序加载 resources.js、i18n.js 后再进入 background.js（Firefox 模块上下文无 importScripts）
- [ ] 重复提交（同一链接快速两次）确认去重

## 队列、计划与抓取

- [ ] 各队列并发上限与限速（主/夜间/自定义）生效且互不影响；夜间任务直接迁移到自定义队列；每站点连接上限含子域
- [ ] 夜间队列窗口（启动/停止时间、重复星期）；全部完成后动作（关机/睡眠/运行程序、重复星期、手动停止不触发）
- [ ] 周期同步：304 顺延、200/206 变更后原子替换、无版本标识报告原因、原文件被用户修改时取消替换；对话框“立即同步”返回未变化/已开始更新，未启用周期时提示先设置周期
- [ ] 流量配额（日/周/月）用完暂停、到期恢复；抓取项目周期执行且同地址去重
- [ ] 站点抓取：深度递归、类型过滤、登录抓取、按来源页保留目录（越界链接平铺）

## 网络与代理

- [ ] 环境 / 直连 / 手动 / 系统代理四种模式；按协议分别代理（HTTP/HTTPS 分流）
- [ ] 系统代理读取：Windows 注册表、macOS scutil、Linux GNOME 与 KDE 各自验证；PAC（Windows WinHTTP）按目标求值、缓存生效
- [ ] 代理 Basic 认证与密码保护（DPAPI）；Windows 集成认证（Negotiate/NTLM，含 HTTPS 隧道 CONNECT 层、UAC 无关）
- [ ] 代理协商最后一轮的服务端令牌正确处理；缺失或无效的 Kerberos 最终令牌不得放行；并行任务不共用已认证连接；CONNECT 的分块 407 可正常协商，无法界定长度或超过大小限制时应报错，取消握手能及时结束
- [ ] Windows SSPI 完成协商后检查实际上下文标志；仅请求双向认证但未实际获得时不得接受，Negotiate 的完成或直接选择状态及 NTLM 回退在域环境中分别验证
