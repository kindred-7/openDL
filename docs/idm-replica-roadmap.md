# IDM 复刻与超越：细节清单与实现规划

> 本文为历史规划，不作为当前功能已完成的证明。2026-10-28 的源码功能对照与未完成项见 [IDM 功能对照](idm-feature-parity.md)，引擎边界见 [下载功能差距](download-gap-analysis.md)。实际构建、测试和运行确认均由用户手动执行。

目标不是"再做一个 IDM", 而是: 先把下载器的**正确性与捕获深度**做到位(复刻),
再在协议、数据与体验上**超越**(创新)。本文按"细节 → 创新 → 路线"组织,
每项标注可落地的现有模块锚点(pathrec / download / api / extension)。

## 0. 现状基线（OpenDL 已具备）

- pathrec: 宽容 URL 提取、IDM 同款文件名推导(RFC 5987/2047/CP1252)、掩码/站点规则
- download: 动态分段调度(chunkQ, 对应 FindMaxFreeChunk)、8 连接 Range、WriteAt 并行写、
  取消/暂停、每块重试
- api + cmd/idmhost + extension: 嗅探→原生消息→桌面下载闭环
- MyGo 仪表盘 UI(表格/KPI/详情面板)、测试/vet/构建流水线

## 1. 复刻对齐: 必须抠的细节

### A. 下载引擎正确性(最易翻车, 优先级最高)

1. **HTTP 语义边角**
   - Range 被服务器忽略: 对 Range 请求返回 **200 而非 206** → 必须识别并降级单流,
     否则多连接写同一文件 = 损坏。同样核对 Content-Range 与总长。
   - **Content-Encoding: gzip 与 Range 冲突**: Range 请求必须带
     Accept-Encoding: identity, 否则字节区间错位。
   - 无 Content-Length(chunked/直播) → 单流、进度未知、禁用分片。
   - **重定向语义**: 301/302 对 POST 降级为 GET, 307/308 保持方法; 每跳更新
     Host/Cookie/Referer; 跳数上限 20 + 循环检测。
   - 认证: Basic/Digest/NTLM/Bearer; 401/407 弹凭据框 + 站点登录表(IDM 的
     Sites Logins), 按 host+realm 缓存。
   - **短时效签名 URL**(网盘/CDN): 过期(403)时自动回页面/接口重取直链
     (IDM 的 "IDM is waiting for the new address to resume the file")。
   - 429/503 读 Retry-After, 全局限速; 服务器限连接数时按站点自动降到 1
     (IDM 的 Options->Connection 站点例外表)。
   - HEAD 不可靠(部分站点禁) → 用 GET Range: bytes=0- 探测。
2. **断点续传的正确实现**
   - 块完成后先同步文件数据，再原子提交并持久化完成记录；重启后校验记录和本地分段再恢复，避免崩溃时把未落盘的数据当作已完成；
   - If-Range(ETag/Last-Modified)续传, 文件变更整体重下;
   - 无可用服务器校验器时不能仅凭长度或本地修改时间判断资源一致；默认从头下载。
3. **磁盘与文件系统**
   - 稀疏文件预建; FAT32 4GB 限制提示; \? 长路径前缀; 文件名非法字符/保留名
     (pathrec.sanitizeWindows 已有);
   - 杀软/占用导致 rename 失败的重试(IDM: "Access Denied while assembling file parts");
   - 跨卷 rename 降级 copy+delete; 落盘前空间预检(含并行任务总和);
   - MOTW(Zone.Identifier)策略: 保留/清除需产品决策, 默认保留更安全。
4. **并发与调度**
   - 取消延迟 <100ms(我们已用 request context 实现); 暂停=断开但保留位图;
   - UI 进度节流 4-10Hz(现在每 500ms, 可调); 10k 任务行虚拟化(表格分页/增量);
   - 全局连接数上限 + 任务公平调度 + 队列并发度。

### B. 捕获与识别(IDM 真正的护城河)

1. **页面世界注入**(我们缺): 向页面注入脚本 hook fetch/XHR/MSE/媒体元素,
   拦截播放器内部真实地址(HLS manifest、分片 URL)——只靠 content script 的
   DOM/性能表抓不到加密播放器的流。
2. **站点规则 DSL**(pathrec.SiteRule 已有骨架): 服务端下发+热更新规则
   (host 正则 + ^/ 路径正则 + 选择器 DSL), 覆盖无扩展名下载路径。
3. **点击接管**: downloads API + 文件类型白名单 + 强制接管键(IDM 的 Insert/Alt),
   尊重"放行浏览器下载"。
4. **会话质量**: Cookie/Referer/UA 逐跳透传, 登录态复用, 代理配置感知。
5. **直链时效管理**: 捕获缓存 + 过期重捕获 + 会话刷新(见 A.1)。

### C. 协议广度

- HTTPS/HTTP1.1 起步 → FTP(S), **HLS/DASH(解析+合并, 见创新)**, 直播录制,
  大文件(>4GB), 首块优先(边下边播)。
- HTTP/2、HTTP/3(QUIC) 支持见创新 2。

### D. 产品完整性(对齐 IDM 的日常面)

- 新建任务对话框: URL/保存目录/分类/队列/立即或定时; 完成后动作(打开/校验/关机)
- 分类标签、搜索、回收站、拖放、剪贴板嗅探、托盘、系统通知
- 站点登录表、代理、限速、计划任务(时段+流量配额)
- 国际化、键盘无障碍(焦点/读屏)、便携模式、自动更新

## 2. 超越 IDM: 创新方向

1. **多源聚合下载**(最大差异化): 同一文件的多个镜像/多协议(HTTP+镜像站)同时
   拉, 聚合成一份 —— 单源分片的天花板是单服务器, 多源聚合突破它。
2. **现代协议**: HTTP/2 多流复用(丢包不全流阻塞的替代方案)、**HTTP/3/QUIC**
   (0-RTT、无队头阻塞、移动网络优势) —— IDM 仍停留在 HTTP/1.1 心智。
3. **流媒体原生支持**: HLS/DASH manifest 解析、分片合并、字幕轨、直播录制,
   不依赖浏览器播放器探测。
4. **智能调参**: 起步带宽探测自动选连接数/块大小; 服务器指纹(S3/nginx/网盘)
   匹配策略库; 429 自动退避学习。
5. **完整性与安全**: 下载后自动哈希比对发布方 checksum、签名校验、恶意域名提示;
   **开源可审计**(IDM 闭源是它的软肋)。
6. **跨平台**: MyGo 原生 Windows/macOS/Linux 三端同构; 任务云同步(自托管可选)。
7. **API/自动化优先**: loopback REST(已有) + CLI + Web 控制台 + Webhook/脚本钩子
   (pre/post download), 下载即服务。
8. **数据体验**: 仪表盘统计(已有雏形)、速度历史、磁盘寿命/容量预测、内容去重。
9. **UX 超越**: 命令面板(Ctrl+K 已留位)、键盘全操作、深浅主题(已有)、
   行内批量操作(已有)、多语言。

## 3. 实现路线(每阶段带质量门)

| 阶段 | 内容 | 质量门 |
| --- | --- | --- |
| P0 引擎正确性 | 206/200 检测、identity 编码、重定向语义、续传位图+If-Range、429 退避、限速器、站点连接例外 | 协议矩阵测试(nginx/S3/禁 HEAD/chunked/gzip)、崩溃注入(断电模拟)后校验文件哈希 |
| P1 捕获深度 | 页面注入 hook、规则 DSL 下发、点击接管、直链时效 | 真实站点样本集回归(10+ 站)、扩展权限最小化审计 |
| P2 协议广度 | HLS/DASH 合并、FTP(S)、>4GB、边下边播 | 流媒体样本回放对比(ffprobe 校验) |
| P3 创新 | 多源聚合、HTTP/2+3(quic-go)、智能调参 | 基准测试: 与 IDM/浏览器同文件对比测速脚本(内网限速环境) |
| P4 生态 | 三端打包、自动更新、CLI/Web、插件钩子 | 跨平台 CI、签名发布、升级迁移测试 |

**基准方法**(决定"超越"是否成立): 搭一个可控测试环境 ——
nginx 限单连接速率(如 2MB/s)、高延迟 tc 模拟、多镜像源; 脚本对比
浏览器/IDM/OpenDL 三方的完成时间、崩溃后恢复时间、CPU/内存占用。

## 4. 风险与取舍

- 多连接在"服务器限总带宽/小文件/高延迟卫星链路"无收益 → 必须自动探测降级,
  否则体验反而差(IDM 的连接档位建议同理)。
- WFP/TDI 驱动级监控(IDM 有)收益低、风险高、平台受限 → 不做, 用浏览器 API 与
  页面注入覆盖。
- QUIC 库(quic-go)成熟度与打包体积; RTMP 等老协议投入产出比低 → 排后。
- 短时效 URL 的重捕获需要站点适配 → 用规则 DSL 扩展, 不写死站点代码。
