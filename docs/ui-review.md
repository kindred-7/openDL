# 当前界面评估

> 此文保留评估时的问题记录。用户已授权优化第 2–17 项，当前代码实施情况与验证边界见 `ui-optimization.md`；第 1 项速度图问题按要求保留。

评估日期：2026-10-27。主要依据为 `docs/design.html` 的 CSS、结构和示例状态，辅以当前 MyGo 源码、已有原生渲染预览及 `ui-ux-pro-max` 的导航状态、悬停反馈和焦点可见性指导。

本轮仅阅读、编辑、格式化和只读观察；未运行提交、构建、测试，也未主动切换主题、下载或操作弹窗。当前应用窗口截图被其他窗口遮挡，不作为完整布局的证明。以下视觉结论使用已有预览，不能视为本轮改动后的验证；行为问题标为源码确认或待手动验证。

## 整体结论

界面骨架与模板基本一致：38px 标题栏、46px 工具栏、220px 侧栏、统计卡比例、九列表格、三栏详情和底部状态栏都有对应实现。13px 正文与 400/500 字重适合紧凑的桌面下载管理器，不建议整体放大字体、增加大块留白或引入新的视觉风格。

主要不足在于交互与数据语义：部分按钮只有提示，没有完成其名称暗示的动作；部分字段外观可编辑但实际只读；图表与选择状态存在源码可见的不一致。应先解决可信度与可操作性，再做细节美化。

## 高优先级问题：先保证动作与信息可信

1. **速度图存在单位混用。源码确认。** `chart` 的最大值 `m` 使用 MB/s，历史值 `v` 仍是 B/s，绘制时直接 `v/m`，非零速度可能把曲线画出可视范围；超过 20 MB/s 时，纵轴仍固定显示 0/10/20。历史由引擎事件追加，也不能保证“最近 60 秒”。建议统一单位、用时间戳取样，并让刻度随量程变化。模板的静态曲线形态可以保留。

2. **“已选 N”与实际勾选数可能不同。源码确认。** `filterRow` 使用 `len(pg.checked)`，取消勾选时表中仍可能保留 `false` 条目；过滤后还可能出现已选数大于当前结果数。建议统计值为 `true` 的条目，并明确“当前结果已选”和跨筛选保留的选择。

3. **操作完成提示与实际动作不一致。源码确认。** “移到队列”仅显示成功提示；“站点抓取”仅提示去添加地址；类型按钮实际重置导航，站点/日期按钮仅显示提示。建议逐项接通真实操作，或准确说明当前能力；不要返回虚假的成功反馈。模板是视觉示例，不能作为这些行为已实现的依据。

4. **右键“继续”可能执行暂停。源码确认。** 菜单固定显示“继续”，实际调用 `toggleRow`；运行中任务会被取消并显示已暂停。应按状态显示“暂停”“继续”或“打开文件”，快捷键与文字同步。模板中的“继续”仅对应示例状态。

5. **添加下载字段外观与能力不一致。源码确认，已有弹窗预览支持视觉判断。** “保存到”和“队列”绘制为输入框样式，但 `d1Field` 只有文本；“来源页可选”没有对应输入；“需要登录”没有凭据输入，也未写入下载请求。建议提供真实编辑/选择控件，或明确显示为只读信息。

6. **开始策略与队列配置含义冲突。源码确认。** “开始下载”固定传主队列，而 `addLinks` 在“立即开始”未勾选时把任务放进夜间列表。建议区分主队列等待、夜间队列与立即开始，并让按钮名称和最终去向一致。

7. **任务详情可能呈现推算信息。源码确认。** 分块图来自总百分比，连接速度为总速度除以 8，连接进度再人为偏移；“断点续传”固定显示支持，请求头有占位内容。应接入引擎明细，未知值显示“待探测”或注明估算；连接数应跟随任务配置，而非固定 8。

## 中优先级问题：提升辨识、可读与可操作性

8. **悬停与选中辨识度偏弱。模板自身问题。** 两者使用同一背景，主要靠文字颜色区分。本轮只补 2px 间距；后续建议保留模板低噪声风格，用 Medium 字重、细标记或独立状态令牌强化当前项，并暴露选中语义。

9. **小字号与浅灰信息叠加。模板自身问题。** 11px 计数、主机名、表头和图表刻度较密；`Faint` 用于有意义的计数时需留意对比度。建议先改善灰度和非必要信息密度，避免全局加粗或统一放大。亮暗主题需要分别核对，当前未验证完整无障碍符合性。

10. **限速箭头暗示下拉，但实际只有开关。源码确认。** 当前点击仅切换不限速/5 MB/s。建议提供限速预设与自定义入口，或去掉下拉箭头并用明确的切换语义；升级时保留既有快捷切换能力。

11. **空列表仍显示可用的任务操作。源码确认，已有预览可见。** 无任务时继续、暂停、移动、删除仍按普通按钮呈现。建议按有效选择和下载状态设置禁用及原因说明；保留可用的添加 URL、批量添加等入口。

12. **搜索与排序承诺不完整。源码确认。** 搜索占位文案包含“输入命令”，未见命令解析；“名称 ↑”是静态文字，没有排序切换。建议兑现能力或修改文案，排序方向应反映真实顺序。

13. **键盘与辅助技术语义需要补齐。源码检查，行为待用户验证。** 剪贴板监听是可点击文本，限速开关是按钮，页签和导航未显式暴露当前选中状态。菜单展示 Enter/Alt Enter，但未见相应处理。建议使用匹配角色，统一作用域快捷键、焦点样式和状态反馈。

14. **弹窗焦点、错误与后台快捷键隔离需核对。源码检查，未交互验证。** 当前使用通用 Overlay，未见明确的进入焦点、关闭后恢复和焦点约束；删除/复制等命令在页面级注册，应确保输入字段与弹窗优先处理。无有效 URL 时会提示但调用方仍关闭弹窗。建议保留输入并在字段旁显示错误；这属于操作反馈，不新增确认或审批流程。

15. **详情区与长内容需更灵活。已有最小窗口预览及源码支持。** 640px 高时详情占据较多高度，任务可视行较少；URL/目录被截断，日志区未见独立滚动。建议允许折叠/调整详情高度，提供完整值提示或复制入口，并为日志独立滚动，默认布局仍保持模板三栏。

## DX 与 AX 问题

16. **样式来源重复且描述冲突。源码确认。** 存在 `style.Palette`、`style.Rules`、`d1Palette` 等层次，颜色和组件状态重复；文档曾把原值与 Radix 混称。建议保留一个权威语义令牌层、统一按钮和表格规格，逐步兼容旧入口，避免一次性替换造成行为回归。

17. **模板、实现与验证证据需要清晰分离。** 模板静态数据不等于业务事实，历史预览不等于当前修改后的效果。建议维护“模板要求—共享令牌—组件实现”的对应表；新改动记录范围及未执行的验证，由用户手动构建、测试，不引入新审批。

## 本轮已实施与边界

- 菜单项增加共享常量 `style.NavItemGap = 2`，应用于每项的固定下边距，不随悬停或选中改变；既有导航、点击和键盘行为未修改。
- 根目录 `AGENTS.md` 写入五条用户规则及 `design.html` 作为主要模板的约定。
- `docs/design-rules.md` 标明最新 Radix 要求、当前 zinc 实现状态及菜单间距调整。
- 其余问题仅作评估与建议，未扩展修改业务逻辑或整体配色；未运行提交、构建、测试。2px 间距对最小窗口底部卡片余量的影响仍需用户手动查看。

建议处理顺序：速度图单位与选择计数 → 操作/提示一致性 → 表单与队列策略 → Radix 统一及导航状态 → 详情区、键盘与长内容。
