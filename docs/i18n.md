# 应用国际化

桌面应用支持简体中文（`zh-CN`）和英文（`en`）。在 **设置 → 常规 → 语言** 切换，立即更新主窗口、设置窗口和托盘菜单，并通过原有设置写入队列保存到 `opendl/settings.json` 的 `language` 字段。旧配置保持简体中文；未知语言回退到简体中文，`en-US` 等英文标签归一化为 `en`。

浏览器扩展使用原生 `chrome.i18n` 与 `_locales/zh_CN`、`_locales/en` 语言包，跟随浏览器语言。桌面端与扩展独立选择语言；原生主机读取桌面设置，桌面返回的错误使用桌面语言。扩展名称、弹窗文本、提示、动态计数与发送错误均使用语言包；扩展 ID、原生主机名称和消息结构保持兼容。

## 代码约定

- `i18n/en.json` 保存中文源文案到英文的映射，编译时内嵌，无额外网络请求或依赖。中文直接使用源文案，缺失词条也回退到源文案。
- 主包通过 `tr(source)` 翻译展示文本，其他包使用 `i18n.T(source)`。原始标签可以继续作为内部键；仅在 `Text`、`Label`、`Tooltip` 等展示边界翻译。
- 格式化之前翻译模板，例如 `fmt.Sprintf(tr("已添加 %d 个任务"), count)`。不要先拼接用户数据再查词条；新句子优先使用完整模板，方便调整不同语言的语序。
- 全局哨兵错误使用 `i18n.NewError(source)`，保留错误对象身份，并在调用 `Error()` 时选取当前语言。`errors.Is` 等控制逻辑不依赖翻译后的错误文本。
- 文件名、路径、URL、用户名、自定义分类及队列名称原样显示。状态码、配置键、分类 ID、队列 ID、请求头和协议值保持稳定，不能用翻译结果参与判断。
- `i18n.Set` / `i18n.Locale` 可安全用于 UI 和后台工作线程。业务状态仍由现有线程规则管理。
- 任务日志及带参数的历史错误保留生成时的语言，切换语言不重写历史内容；新事件采用当前语言。

扩展的 `extension/i18n.js` 将源文案映射到消息 ID，通过 `chrome.i18n.getMessage` 获取文字。新增文案需要同时添加映射及两个 `messages.json` 词条；动态参数采用命名占位符，`placeholders` 的 `content` 使用 `$1`、`$2` 等位置参数，不翻译脚本表达式或用户内容。

## 模板差异

相对 `docs/design.html`，常规设置新增语言选项。重复日期和添加任务的选项行允许在空间不足时换行，以容纳英文。继续复用现有 shadcn/ui 风格、Radix 颜色、字体、间距与控件行为。
